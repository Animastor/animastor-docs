## 3. Согласованность: допущения и их проверка

- Запись `book.json` неатомарна (`writeFileSync` без temp+rename) → простое копирование
  нельзя выдать за гарантированно согласованный снимок.
- В backend **нет** режима read-only/maintenance; гарантированная остановка записи =
  остановка контейнера `animastor-backend`, что этим этапом запрещено (и не выполнялось).
- Условия, при которых снимок считается стабильным, проверены до и после копирования:
  - активных генераций нет, активных запросов в PG нет;
  - манифест источника **pass1** (15:07:50) → архив (15:08:09) → пауза 90 с →
    **pass2** (15:13): `diff pass1/pass2` по sha256 **и** по списку файлов — **пусто**;
  - новейший mtime источника до и после: `2026-10-18 03:45:32` — не изменился;
  - `tar` завершился с кодом 0 и **пустым stderr** (нет «file changed as we read it»).
- **Вывод (честно):** получен *стабильный, но не гарантированно согласованный* снимок
  (окно наблюдения ≈ 6 минут, включая паузу 90 с). Гарантия требует окна обслуживания — §7 B3.

Для PostgreSQL согласованность получена штатно: `pg_dump -Fc` использует снимок MVCC
(BEGIN ISOLATION LEVEL REPEATABLE READ) и **не блокирует** писателей. Для Redis использована
процедура, не затрагивающая сервис: файл `dump.rdb` Redis всегда полный (запись во временный
файл + атомарный `rename`), поэтому копирование выполнялось без `BGSAVE` и без остановки —
зафиксировано, что inode/размер исходника **до и после чтения совпали** (`ino=261943`,
`size=25869062`), `rdb_bgsave_in_progress:0`.

```bash
    -C /home/animastor/animastor

# 3) PostgreSQL: сначала в проверочную БД, потом (по решению) в animastor
docker exec -i animastor-pg pg_restore --list < "$B/pg-animastor-2026-10-20.dump" | tail -1
docker exec animastor-pg psql -U animastor -d postgres -c "CREATE DATABASE animastor_restore_check"
docker exec -i animastor-pg pg_restore -U animastor -d animastor_restore_check \
       < "$B/pg-animastor-2026-10-20.dump"
# сверка: docker exec animastor-pg psql -U animastor -d animastor_restore_check -Atc \
#   "select count(*) from books"   (и по остальным таблицам)
# восстановление в animastor — только с остановкой backend и решением владельца

# 4) Redis: проверка RDB и изолированная загрузка

  redis-check-rdb /backup/redis-dump-2026-10-20.rdb          # ожидается "RDB looks OK", 302 keys
```

**Совместимость:** `pg_dump`/`pg_restore` — PostgreSQL **16.14** (текущая версия сервера);
