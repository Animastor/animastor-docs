## 1. Ротация пароля административной учётки

### 1.1 Кто и как менялся

| Параметр | Значение |
|---|---|
| Учётка | `developer` — **единственный** пользователь с ролью `admin` (user_id `92fd6022-57de-4d6f-8e9b-adfcd5028deb`) |
| Механизм | Прямое обновление `users.password_hash` в PostgreSQL (`animastor-pg`) scrypt-хешем, сгенерированным **собственной реализацией бэкенда** `packages/animastor-auth/src/password.js` (`hashPassword`, формат `scrypt$N=16384,r=8,p=1$…`) |
| Почему не API | В бэкенде нет endpoint'а смены/сброса пароля (auth-routes: register/login/logout/me; admin-routes: только system-ai/workers); прямая запись — единственный доступный путь (так же, как и предыдущий пароль, provisioning которого API не покрывал) |
| Активные сессии до ротации | **0** — отзывать нечего было |
| Пароль в файлах/отчётах/логах | **не сохранялся**: передавался в процесс только через переменную окружения короткоживущего процесса; временные файлы удалены; `.bash_history` не содержит ни старого, ни нового значения (проверено) |

### 1.2 Верификация (без вывода секрета)

| Проверка | Результат |
|---|---|
| Локальная `verifyPassword(новый, новый_хеш)` тем же модулем бэкенда | `true` |
| Отпечаток хеша в БД до/после (`md5(password_hash)`) | `6acc314dfae8ab0663f015ae6f2997ea` → **`9f6b48646500d2250b87079f04f36dfd`** (изменён; UPDATE 1) |
| Реальный логин через production-прокси `POST https://app.animastor.org/api/v1/auth/login` | **HTTP 200**, `authenticated: true`, `user.username=developer`, `user.role=admin`, `Set-Cookie` сессии — 1 шт. |
| Негативный тест (неверный пароль) | **HTTP 401** `login_invalid_credentials` |
| Тестовая сессия после проверки | **отозвана** (`revoked_at` установлен) — активных сессий у `developer` снова 0 |

Старый пароль стал мёртвым: логин сверяет пароль только с текущим `password_hash`; хеш заменён, прежнее значение проверить нечем.

### 1.3 Замечания (рекомендации владельцу, не блокируют работу)

1. **Длина пароля: 6 символов при политике приложения `PASSWORD_MIN_LENGTH = 8`** (`packages/animastor-auth/src/password.js:25`; policy применяется при register/смене через API, login её не проверяет). Предыдущий (утёкший) пароль тоже был 6-символьным, т.е. provisioning вне API повторён. Рекомендуется в ближайшее время сменить на пароль длиной ≥ 8 — например, сообщить новый пароль владельцу отдельно, и я обновлю его тем же проверенным способом.
2. **Новый пароль был передан владельцем в чат** и потому существует в локальных транскриптах инструмента (`~/.local/share/opencode/…`, отмечено в Stage 82). В репозиториях, отчётах и артефактах его нет; публикация его не содержит.
3. Старый пароль остаётся в публичных историях web/backend, в `/tmp`-артефактах и zip-снапшотах (перечень — Stage 82 §1.1), но теперь **мёртв**; очистка/удаление этих носителей — по решению владельца, срочности не имеет.
