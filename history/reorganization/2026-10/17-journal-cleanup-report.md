Таким образом системная (root) часть журнала ≈ **3,4 ГБ** и требует root для vacuum.

### Доступные диагностические события (сохранены; без секретов)

Пользователь `animastor` **не входит в группы `adm`/`systemd-journal`** —
системный журнал и dmesg недоступны:

- `journalctl -p err --since "-7 days"` (видимая часть): только события уровня err
  за 11–12 Oct — **`sudo[...]: pam_unix(sudo:auth): conversation failed /
  auth could not identify password for [animastor]`** (неудачные попытки
  вызова sudo, в т.ч. наши штатные проверки этапа) и одна запись
  `sshd: Disconnected from user animastor` (штатное завершение сессии 12 Oct 02:58).
  **Критических событий (OOM, panic, отказы сервисов) в видимой части нет.**
- `dmesg -T` → `read kernel buffer failed: Operation not permitted`.
- Чтение файлов журнала: `/var/log/journal/…/system.journal` → **NOT readable**
  (`root:systemd-journal`, mode 640, ACL `+`).

**Ограничение:** содержимое системного журнала (≈3,4 ГБ) перед очисткой
просмотреть нельзя — любые potentially important system diagnostics
доступны только root. Это зафиксировано как риск: событие, которого нет
в видимой пользователю части, проверить до удаления невозможно.

## 2. Действие

Регламент: *«Если root-доступ отсутствует или команда завершается ошибкой,
остановиться и указать причину.»*

Попытка выполнения задокументированной команды:

```
$ sudo -n journalctl --vacuum-size=200M
sudo: a password is required
exit=1
```

**Команда НЕ выполнена.** Причина: пользователь `animastor` не входит в группу
`sudo` (только `ubuntu`, `sureg`), sudo требует пароль, который у агента
отсутствует. Пароль не запрашивался и не подбирался.

Не выполнялось (по ограничениям этапа): ручное удаление файлов журнала,
изменение настроек systemd-journal (`/etc/systemd/journald.conf`),
повторный vacuum без root (этап 16 уже подтвердил: 0 байт выигрыша).

  ровно одно и оно задокументировано:

- **Production не перезапускался, health endpoints 200/200.**

  (по состоянию на хосте: `ubuntu`, `sureg`).
