### 5.2 Transaction boundaries and safety envelope

```sql
BEGIN;
SET LOCAL lock_timeout = '5s';
SET LOCAL statement_timeout = '120s';
LOCK TABLE scene_assets IN SHARE ROW EXCLUSIVE MODE;   -- blocks runtime INSERT/UPDATE/DELETE for this txn only;
                                                        -- readers (ACCESS SHARE) keep working
-- P1…P12 assertions, then batches A → B1 → B2, then in-txn post-assertions (§6.8), then COMMIT;
-- any assertion failure raises an exception ⇒ psql -v ON_ERROR_STOP=1 exits ⇒ automatic ROLLBACK of everything.
```

- **Batch A + B1 + B2 run in ONE transaction** (repoint must be visible to the B1 canonical guard; deleting a
  duplicate and losing its canonical in the same operation must be impossible).
- **Batch C (4 dead-path rows) runs in a SEPARATE, later transaction**, only after the archive gate of §7 is
  satisfied; it also has its own snapshot + assertions + rollback.
- Every mutation is executed through a `DO` block that captures `ROW_COUNT` and raises unless it equals the
  expected number — **row-count assertions are mandatory, not advisory**.
- Rollback behavior: (i) assertion failure ⇒ automatic full rollback of the open transaction; (ii) after a
  successful commit, if post-checks §6.8 fail ⇒ restore the affected rows from the pre-migration snapshot
  (`pg_dump -t scene_assets` + JSON manifest, both SHA-256 recorded before execution) — restoring by `id` is safe
  because `scene_assets` has **no foreign keys, no views, no triggers, no partitions** (§6.1); (iii) no Redis,
  file or code rollback is needed because none of them is touched.

```sql
        WHERE c.book_id = d.book_id AND c.chapter_id = d.chapter_id
          AND c.scene_id = d.scene_id AND c.asset_type = 'audio'
          AND c.build_id IS NOT NULL AND c.path IS NOT NULL
          AND (d.path IS NULL OR c.path = d.path))
    AND NOT EXISTS (                 -- belt & braces: never empty a key
        SELECT 1 FROM scene_assets r
        WHERE r.book_id = d.book_id AND r.chapter_id = d.chapter_id
          AND r.scene_id = d.scene_id AND r.asset_type = 'audio'
          AND r.id <> d.id);
  GET DIAGNOSTICS n = ROW_COUNT;
  IF n <> 17 THEN RAISE EXCEPTION 'BATCH B2: rowCount=% expected=17 -> ROLLBACK', n; END IF;
  SELECT md5(string_agg(id::text, ',' ORDER BY id)) INTO md
    FROM scene_assets WHERE build_id IS NULL AND asset_type = 'audio';
  IF md IS NOT NULL THEN RAISE EXCEPTION 'BATCH B2: leftover audio NULL rows (%s)', md; END IF;
END $$;
```

The `EXISTS(canonical)` clause is evaluated **per deleted row inside the same guarded operation** — a versioned
counterpart must be present for that exact key (and its path must match when the NULL row declares one).

## 10. Risks and open items for the executing stage
