# Карточка героя

Статус: **web реализован** в ветке `feat/hero-card` (`animastor-web` `b80b24e`, 2026-11-12) на контракте VBook v4;
**Android — спецификация** (§8, GAP в [`ANDROID_WEB_PARITY.md`](../architecture/ANDROID_WEB_PARITY.md)). Работает
только с backend шагов 1–4 [`VBOOK_FORMAT_V4.md`](../architecture/VBOOK_FORMAT_V4.md) §12; до него не выкатывается.

Формат героя, API и коды ошибок — `VBOOK_FORMAT_V4.md` §4, §8.2, §9, §10.3. Здесь — только поведение экрана.

## 1. Что заменяет

Вкладки редактора «Персонажи», «Голоса», «Поведение» заменены одной вкладкой **«Герои»**. Вкладок стало 7:
Глобальные · Глава · Сцена · Аудио · Модуль · Герои · Локации; вкладка по умолчанию — «Модуль», как раньше.

Прежние сценарии и где они теперь:

| Было | Стало |
|---|---|
| «Персонажи»: правка имени и паспорта, «Сохранить» вкладки | карточка героя: «Имя», блок «Внешность», «Сохранить» карточки |
| «Персонажи»: «+» → диалог (id, имя, паспорт) | плитка «Добавить героя» → диалог (тип, имя, id) → открывается карточка |
| «Персонажи»: «−» → подтверждение → удаление с каскадом голоса и поведения | «Удалить героя» внизу карточки → подтверждение; удаляется файл героя целиком |
| «Голоса»: правка `instruction` | блок «Голос»: «Тембр» и «Манера» |
| «Голоса»: «+» / «−» голоса без героя | герой типа «Только голос»; «Убрать» в блоке «Голос» |
| «Голоса»: запись `narrator` | карточка «Диктор» — всегда первая в сетке |
| «Поведение»: `baseline`, привычки и реакции построчно | блок «Привычки», те же три поля и те же правила разбора строк |
| «Поведение»: «+» с выбором героя, «−» записи | поля есть у каждого героя; пустые поля = записи нет |
| правила поведения — только чтение, без UI | список правил героя с выключателем, добавление, удаление |
| блоки паспорта во вкладке «Сцена» (переопределения сцены) | без изменений |

## 2. Сетка

Вкладка «Герои» — сетка плиток (`repeat(auto-fill, minmax(140px, 1fr))`: 2 в ряд на телефоне, 4–6 на десктопе).

Плитка: портрет 3:4 в рамке → имя → роль → строка характеристик.

- Портрет — первая референс-картинка с `kind: "portrait"`, иначе первая картинка, иначе монограмма (до двух
  инициалов имени, без имени — id). У диктора вместо монограммы — значок динамика. У героя «Только голос» рамка
  пунктирная.
- Имя: `name`; без имени — id; у диктора — «Диктор».
- Роль: `role`; без роли — тип («Герой» / «Только голос» / «Диктор»).
- Характеристики: внешность — 3 ромба (заполнены `appearance`, `clothes`, `video_tokens`); голос — 2 ромба
  (`timbre`, `manner`) и точка состояния референса (зелёная — закреплён, жёлтая — не закреплён, красная — файл не
  найден или изменён, серая — нет); «привычки N/M» — включённых правил из всех. Блока нет — нет и его значка.
- Порядок: диктор, затем порядок сервера (`structure.characters_order`).
- Последняя плитка — «Добавить героя». Битые файлы героев — красные плитки перед ней (§7).

Открытие сетки не делает ни одного запроса: данные — из уже загруженной книги.

## 3. Карточка

Нажатие на плитку открывает карточку **на месте сетки** (не модальное окно): на телефоне — весь экран вкладки, на
десктопе — область инспектора. Сверху липкая строка: «‹ К героям» и «Сохранить».

Раскладка: одна колонка до 736px; шире — две: слева личность (240px), справа характеристики.

| Блок | Содержимое | У диктора |
|---|---|---|
| Личность | портрет, имя, чипы типа и роли, id (только чтение); поля «имя», «роль», «алиасы» (по одному на строку), «заметки» | портрет, id, «имя», «заметки» |
| Внешность | «внешность», «одежда», «видео-токены» (через запятую, 1–4); «Убрать» / «Добавить внешность» | нет |
| Голос | «тембр», «манера», «Что получит синтез речи» (раскрывает `join(timbre, manner)`), референс (§6); «Убрать» / «Добавить голос» | есть, без «Убрать» |
| Привычки | «базовое поведение», «привычки», «реакции»; правила (§5) | нет |
| Референсы | референс-картинки: загрузка, «Сделать портретом», удаление | нет |
| — | «Удалить героя» | нет |

Подсказки под полями: алиасы — «как автор называет героя в тексте»; заметки — «только для вас: в генерацию не
попадают»; тембр — «по этому тексту создаётся референс».

«Манера» при закреплённом референсе на звук не влияет (клон копирует подачу референса —
`VBOOK_FORMAT_V4.md` §5.1); подсказка поля в этом состоянии: «С закреплённым референсом подачу задаёт сама запись».

## 4. Сохранение

- Текстовые поля правятся в черновике. «Сохранить» активна, только когда черновик отличается от героя и проходит
  проверку; при несохранённых правках подпись — «Сохранить *».
- Один запрос: `PATCH /book/:id/heroes/:heroId {fields, if_rev}`. В `fields` — **только изменённое**: пустой текст →
  `null`; списки (алиасы, токены, привычки, реакции) — массивами; снятый блок — `passport: null` / `voice: null`;
  добавленный пустой блок — `passport: {}` / `voice: {}`.
- Списочное поле сравнивается через тот же текст, что показан в карточке: нетронутое поле не отправляется никогда —
  неизвестные ключи внутри хранимых реакций не теряются.
- После успеха книга перечитывается (`GET /book`), черновик заменяется данными сервера.
- 409 `rev_conflict` — «Героя изменили в другом месте. Откройте карточку заново — правки не сохранены»; черновик
  остаётся на экране.
- Пришли новые данные книги, а в карточке есть несохранённые правки — черновик не трогается.
- «‹ К героям» при несохранённых правках — диалог «Не сохранять» / «Вернуться к карточке».
- Проверки черновика (те же на сервере): у героя с внешностью есть имя; видео-токенов не больше 4; алиасов не
  больше 64; алиас не равен имени.
- Общая кнопка «Сохранить» редактора на вкладке «Герои» скрыта (мобильная нижняя) либо ничего не отправляет
  (десктопная в шапке).

Действия без черновика, выполняются сразу и перечитывают книгу: выключатель правила, добавление и удаление правила,
закрепление и открепление референса, загрузки, «Сделать портретом», удаление картинки.

## 5. Правила поведения

Строка правила: выключатель · фраза действия (`then.action`) · чипы эмоций (`when.emotion`) · вероятность в
процентах · «×». Выключенное правило приглушено.

- Выключатель — `PATCH …/rules/:ruleId {fields: {enabled}}`.
- «Добавить правило»: действие (английский, без подлежащего), эмоции — чипы словаря из 15 значений
  (`VBOOK_BEHAVIOUR.md` §3), вероятность (по умолчанию 0.35). Кнопка активна при заполненном действии и хотя бы
  одной эмоции. Id — `<id героя>.<первые три слова действия>`, уникальный среди всех правил книги (с суффиксом
  `_2`, `_3`, …). Остальные поля правила — дефолты сервера.
- Правка существующего правила (кроме выключателя) — удалить и добавить.
- Глобальные правила и лимит на сцену в карточке не показываются (уровень книги).

## 6. Референс голоса

Блок внутри «Голоса». Заголовок: состояние (нет / не закреплён / закреплён / файл не найден / файл изменён) и
результат проверки (`verification`).

- **Закреплённый**: плеер, произнесённый текст (`ref_text`), строка «источник · модель · seed · файл»,
  «Открепить». При состоянии `missing` / `mismatch` вместо плеера — пояснение, что делать.
- **Кандидаты**: у каждого плеер, строка «файл · источник · проверка», «Закрепить». Закреплённый в списке не
  повторяется.
- **«Создать кандидатов»** — единственная команда генерации в карточке. Выполняется только по этому нажатию; в
  запросе — `client_action {kind: "user_click", source: "hero_card.voice_design", action_id, trusted}`, как у
  `/regenerate` ([`COMMAND_ONLY_GENERATION.md`](../architecture/COMMAND_ONLY_GENERATION.md)). Недоступна, пока тембр
  пуст или изменён и не сохранён. Пока команда выполняется (`pending`), список кандидатов перечитывается раз в 3 с.
- **«Загрузить свой»** — выбор файла (wav, flac, mp3, ogg) + поле «текст в загружаемой записи».
- Открытие карточки только **читает** список кандидатов.
- Сервер без этих маршрутов (404 / 405 / 501) — в блоке «Референсы голоса на этом сервере пока недоступны»;
  остальная карточка работает.

Маршруты, которых ждёт карточка (заводит задача референсных голосов; префикс `/book/:id/heroes/:heroId`):

| Маршрут | Назначение |
|---|---|
| `GET /voice/candidates` | `{candidates: [{name, file, sha256, ref_text?, source?, model?, seed?, verification?, duration_ms?, pinned?, state?}], pending?}` |
| `POST /voice/candidates/design` | `{count, client_action}` — команда генерации |
| `POST /voice/candidates/upload` | multipart: `file`, `ref_text` |
| `POST /voice/reference` | `{name, locked: true}` — закрепить кандидата |
| `DELETE /voice/reference` | открепить (файл остаётся) |
| `GET /voice/file/:name` | аудио для плеера |
| `POST /image-refs` | multipart: `file`, `kind` |
| `PATCH /image-refs/:index` | `{fields: {kind}}`; `kind: "portrait"` снимает `portrait` с остальных |
| `DELETE /image-refs/:index` | удалить ссылку и файл |
| `GET /image-refs/:index/file` | картинка |

Первая загруженная картинка получает `kind: "portrait"`, следующие — `other`.

## 7. Ошибки и особые состояния

| Состояние | Экран |
|---|---|
| Книга 3.1 (`unsupported_vbook_version`) | вместо редактора: «Формат книги не поддерживается. Книга сохранена в формате VBook 3.1… Импортируйте исходный текст заново». Без повторных попыток загрузки. Тот же текст — при импорте и на любом экране, который показывает ошибку запроса |
| Битый файл героя (`hero_issues`, `blocking: true`) | красная плитка: id или имя файла, «Файл героя повреждён», текст причины, «Удалить файл» → подтверждение → `DELETE …?broken=1` |
| Предупреждение по герою (`blocking: false`) | жёлтая строка вверху его карточки |
| Открытый герой исчез (удалён в другом месте) | возврат в сетку |
| Ошибка действия | красная строка вверху карточки; данные на экране не меняются |
| Нет героев | «В книге пока нет героев» и плитка «Добавить героя» |

Диалог добавления: тип («Герой» — создаётся с пустой внешностью; «Только голос» — с пустым голосом), имя
(обязательно), id (необязателен; проверяется на месте: латиница, цифры, подчёркивание, до 64; не зарезервирован; не
занят). Пустой id — сервер строит из имени. Диктор не создаётся и не удаляется.

## 8. Android — спецификация паритета

Экран повторяет web; отличия только платформенные.

- `EditFragment`: вкладки «Персонажи», «Голоса», «Поведение» → одна «Герои» (те же 7 вкладок и ключи строк).
- Сетка — `RecyclerView` + `GridLayoutManager` (2 колонки, 4 на планшете); карточка — отдельный `HeroFragment`
  поверх редактора (системная «назад» = «‹ К героям», тот же диалог несохранённых правок).
- Модели: `BookData.heroes: List<Hero>`, `hero_issues`, `behaviour`; `characters`, `voices`, `behaviors`,
  `behavior_rules`, `BehaviorEntries.kt` удаляются.
- Чистая логика — `repository/HeroModel.kt`, один в один с `features/heroes/heroModel.ts`: порядок, тип, статистика,
  портрет, черновик и его разница, проверки id и черновика, разбор строк, id нового правила,
  `unsupportedVbook`. JVM-тест `HeroModelTest` на тех же фикстурах (`heroFixtures.ts` =
  `architecture/schemas/examples/*.json`) и тех же случаях, что `heroModel.test.ts`.
- Строки — те же ключи `hero_*`, `heroes_*`, `vbook_unsupported_*`, `edit_heroes_tab` (ru + en).
- Плеер референса — `MediaPlayer` по тому же URL; загрузка файлов — системный выбор документа.
- Ошибка формата 3.1 — тот же текст на экранах редактора, плеера, генератора и импорта.

## 9. Web: что сделано и что осталось

Сделано (`animastor-web` `feat/hero-card`, `b80b24e`; vitest 340/0, `tsc --noEmit` и `vite build` — без ошибок):

- `frontends/app/src/features/heroes/`: `heroModel.ts`, `heroApi.ts`, `HeroesPanel.tsx`, `HeroCard.tsx`,
  `heroFixtures.ts`; тесты `heroModel.test.ts` (35), `HeroesPanel.test.tsx` (19).
- `pages/EditPage.tsx` — вкладка «Герои» вместо трёх; состояние «формат не поддерживается».
- `api/models.ts` (`heroes`, `hero_issues`, `behaviour`), `api/client.ts` (`postForm`, единый текст ошибки 3.1),
  `app/i18n.ts` (ru + en), `styles/base.css`; `api/behaviors.ts` удалён.

Проверено тестами: сетка и карточка не вызывают генерацию и запись при открытии; PATCH несёт только изменённые поля
и `rev`; `client_action` в команде кандидатов; деградация блока референсов на 404; подтверждения удаления;
диктор без лишних блоков.

Не проверено: карточка **не открывалась в браузере против живого сервера** — backend v4 не существует; вёрстка
проверена только сборкой и DOM-тестами.

Осталось (шаг 5 плана):

1. Пройти карточку вручную на тестовом стеке после шагов 1–4: телефон и десктоп, обе темы.
2. Остальные потребители книги в web на форму v4 — проверить `@animastor/web-player`, `web-navigator`,
   `web-book-session`, чат ассистента (в коде приложения обращений к `characters` / `voices` вне редактора нет;
   пакеты проверить отдельно).
3. Экран «формат не поддерживается» в плеере, генераторе и списке книг (`unsupported: true`) — сейчас там общий
   текст ошибки запроса.
4. `@animastor/web-editor` 0.2.0: убрать типы сущностей `character`, `voice`, `behavior` и `BehaviorAddDialog`
   (приложение ими больше не пользуется); ключи i18n `entity_*_character|voice|behavior`, `edit_no_characters|voices|behaviors`.
5. Книги на legacy-оркестрации: команда кандидатов вернёт отказ сервера — показать его текст в блоке референса
   (сейчас — общая строка ошибки карточки).
6. Словарь эмоций отдавать с сервера (сейчас константа `BEHAVIOUR_EMOTIONS` — копия `behaviour-emotions.js`).
