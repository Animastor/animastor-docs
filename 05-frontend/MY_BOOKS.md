# «Мои книги» — Библиотека, вкладки, действия с книгой

> Нормативный документ. Введён 2026-11-22 (задача владельца «Мои книги»).
> Фронты: web `animastor-web` `frontends/app`, Android `animastor-android`;
> backend `animastor-backend`. Паритет — `architecture/ANDROID_WEB_PARITY.md`, раздел «Мои книги».

## 1. Экран

Экран «Библиотека» — две вкладки:

| Вкладка | Web | Android | Содержимое |
|---|---|---|---|
| **Мои книги** | `/library?tab=mine` (и `/library` без `tab`) | `LibraryFragment`, вкладка `LibraryTab.MINE` | книги workspace пользователя |
| **Общая библиотека** | `/library?tab=public` | `LibraryFragment`, вкладка `LibraryTab.PUBLIC` | заглушка «Скоро» |

Встроенная публичная страница `/library` (web — iframe, Android — WebView `app.animastor.org/library`) больше
не показывается.

**Один экран для всех ярлыков.** «Мои книги» — не отдельный экран, а «Библиотека» на вкладке «Мои книги»:

| Откуда | Web | Android |
|---|---|---|
| Файл → карточка «Библиотека» | `navigate('/library')` (вкладка по умолчанию — «Мои книги») | `MainActivity.openLibrary()` |
| Настройки → пункт «Мои книги» | `router.openMyBooks()` → `/library?tab=mine` | `MainActivity.openMyBooks()` |
| Меню аккаунта (значок пользователя в шапке) → «Мои книги» | `router.openMyBooks()` | `AuthDialog.show(…, onMyBooks = { openMyBooks() })` |

Android: `LibraryFragment` создаётся только в `MainActivity.openLibrary`; уже открытая «Библиотека» лишь
переключает вкладку. Пункт меню аккаунта есть только у вошедшего пользователя (у анонима книг нет).

## 2. Список «Мои книги»

Источник — `GET /api/v1/books?limit=500` (книги workspace вызывающего; §4). Порядок — **недавно открытые
сверху**: по `last_opened_at`, книга, которую не открывали, — по `updated_at_ms` (то же правило на сервере и
в клиентах: web `myBooksModel.sortMyBooks`, Android `MyBooksModel.sort`).

Строка книги:

- **название** (`title`, иначе `book_id`);
- **формат** — «VBook 4» / «VBook 3.1» (`vbook_version`);
- **дата** — «Открыта <дата>» (`last_opened_at`) или «Изменена <дата>» (`updated_at_ms`);
- кнопка **«Открыть»**;
- меню (⋮): **«Удалить сгенерированный контент»** и **«Удалить книгу»**.

«Удалить сгенерированный контент» неактивен, если сервер сообщил `has_generated_content: false`
(`null` — неизвестно, пункт активен).

**Книга 3.1** (`unsupported: true` или мажорная версия ≠ 4) — пометка **«устаревший формат»**, без «Открыть»,
в меню только «Удалить книгу» (`VBOOK_FORMAT_V4.md` §9).

**Пустой список** — приглашение: **«Создать книгу»** (как карточка «Создать» на экране «Файл»: пустая книга →
редактор) и **«Открыть файл»** (выбор файла → импорт → экран «Файл» показывает ход импорта).

**Аноним** — подсказка «Войдите, чтобы увидеть свои книги», запроса списка нет.

## 3. Действия

Обе операции удаления — **только после подтверждения**, в тексте подтверждения **название книги**:

| Действие | Запрос | Текст подтверждения (ru) |
|---|---|---|
| Удалить сгенерированный контент | `DELETE /api/v1/book/:id/cache` | «Удалить сгенерированный контент книги «{название}» (изображения, аудио, видео) с сервера? Текст книги, герои и референсы голосов останутся; контент придётся сгенерировать заново.» |
| Удалить книгу | `DELETE /api/v1/book/:id` | «Удалить книгу «{название}» с сервера вместе со всем её содержимым? Это действие необратимо.» |

Подтверждение одно на оба фронта и на все места (список, экран 3.1 на «Файле», состояние 3.1 в редакторе):
web `features/myBooks/ConfirmBookAction.tsx`, Android `ui/MyBookActions.kt`; ключи строк
`my_books_delete_content_confirm` / `my_books_delete_book_confirm`.

Если действие касается книги, **открытой на этом устройстве**: «удалить контент» сбрасывает плеер и прогресс
(книга остаётся открытой — её структура цела); «удалить книгу» закрывает книгу. После действия список
перечитывается с сервера.

**«Открыть»** — тот же поток, что deep link `?book=<id>` (web `fileStore.openBookById`, Android
`GenerateViewModel.openBookById`): загрузка книги, плеер, затем экран «Плеер», если у книги есть медиа, иначе
«Генератор». Если сервер всё же ответил `409 unsupported_vbook_version` — экран «Файл» с состоянием 3.1.

**«Книга открыта».** Открытие книги (из списка, импорт, создание, deep link) отправляет
`POST /api/v1/book/:id/opened` — без ожидания ответа; сбой не мешает открытию. Восстановление сессии при
запуске приложения «открытием» не считается.

## 4. Backend

### `GET /api/v1/books`

Книги workspace вызывающего (как и раньше; аноним — `{books: []}`, кэш `no-store`). Добавлены поля
каждой записи:

| Поле | Тип | Смысл |
|---|---|---|
| `vbook_version` | number \| string \| null | формат книги из манифеста (у 3.1 — из ошибки версии) |
| `unsupported` | `true` \| нет | книга неподдерживаемого формата (было и раньше) |
| `last_opened_at` | number (epoch ms) \| null | когда владелец последний раз открыл книгу |
| `updated_at_ms` | number (epoch ms) \| null | `updated_at`, приведённый к ms (`updated_at` остаётся в исходном виде — ISO-строка или epoch-секунды); нет `updated_at` (пустая книга до первой правки) — `manifest.created_at` (post171; `updated_at` при этом остаётся `0`) |
| `has_generated_content` | boolean \| null | есть ли у книги то, что удалит `DELETE /book/:id/cache` (не считая `voices/`) |

`limit` — по умолчанию 20, максимум 500. Порядок — §2. Сбой чтения `last_opened_at` (PG недоступен, миграция
не прошла) теряет только порядок, не список.

### `POST /api/v1/book/:id/opened`

Записывает `books.last_opened_at = now (ms)` и **больше ничего**: не генерирует, не запускает анализ, не
трогает файлы книги и `books.updated_at`. Ответ `{book_id, last_opened_at}`. Доступ — общий guard
`/api/v1/book/:bookId` (`requireBookAccess`): аноним **401**, чужая или несуществующая книга **403**. Книга 3.1 —
**409** `unsupported_vbook_version` (для неё разрешено только удаление; её порядок в списке — по `updated_at`).

Колонка — миграция **MB-1**: `books.last_opened_at BIGINT NULL` (аддитивная, без заполнения).

### Удаление контента — `DELETE /api/v1/book/:id/cache`

Существующий маршрут. Удаляет сгенерированные артефакты книги в `OUTPUT_DIR`, ключи Redis генерации, строки
PG сгенерированного/кэша и чаты ассистента. **Не трогает:** `voices/` (референсы голосов,
`VOICE_REFERENCES.md`), текст и структуру книги (`data/books/<id>/`), строки `books`, `book_source`,
`book_snapshots`, `book_events`. Проверено тестом `backend/tests/my-books.test.js`.

Каталог сборки VBook 4 / orchestration v2 — `OUTPUT_DIR/<manifest.build_id>/`; книга v2 может не иметь чанков
Redis, которые его называют, поэтому маршрут добавляет `manifest.build_id` к найденным по чанкам (исправлено
2026-11-22; до этого контент такой книги мог не удаляться). То же — в каскаде `DELETE /book/:id`
(`book-deletion.cjs`: `build_id` бандла, прочитанный через `book.loadBook` до удаления книги, — тот же, что
каскад читает для очистки IU-реестра).

### Удаление книги — `DELETE /api/v1/book/:id`

Штатный каскад `services/book-deletion.cjs`, без изменений, кроме `manifest.build_id` выше и правила общего
каталога сборки:

- **Один `build_id` мог быть у двух книг.** `.vbook`, импортированный под другим `book_id` с тем же
  `manifest.build_id`; две пустые книги, созданные в одну миллисекунду (`manual_<ms>`). Файлы артефактов
  названы с префиксом `book_id` и делятся по владельцу (`book-artifacts.cjs`), а `voices/` принадлежит каталогу
  сборки, а не книге.
- **Новые книги своего `build_id` больше не делят (post171):** пустая книга — `manual_<uuid>` (не `manual_<bookId>`:
  `book_id` может быть кириллическим, `build_id` — только ASCII, `BUILD_ID_RE`); импорт `.vbook`, чей `build_id` уже
  называет другая книга (PG — `book-repo.buildIdsNamedByOtherBooks`, или её манифест; ошибка PG = «занят»), получает
  `vbook_<uuid>`, записанный в манифест; повторный импорт той же книги свой `build_id` сохраняет. Архив **без**
  `build_id` — как раньше: манифест без него, все потребители берут `'default'`, то есть общий `OUTPUT_DIR/default/`
  (и общий `voices/`) у всех таких книг — не исправлено, см. `reports/2026-11-24/post171-fixes.md`. Уже существующие
  книги с общим `build_id` (если есть) защищает правило ниже.
- Поэтому `build_id`, который называет другая книга — строка PG другого `book_id` в любой таблице с колонкой
  `build_id` (`scenes`, `output_manifests`, `image_units`, `scene_assets`, `iu_image_pointers`,
  `iu_image_fence_reservations`) или манифест другой книги на диске, — **не удаляется каталогом целиком**:
  уходят только записи этой книги, `voices/` и файлы другой книги остаются. Ошибка чтения PG считается
  «общий» (каталог остаётся).
- Тесты `backend/tests/my-books.test.js`: две книги с одним `build_id` (манифесты), общий только в PG, ошибка
  PG, одна книга без чанков Redis — каталог удалён.
- Очистка кэша (`DELETE /book/:id/cache`) это правило не использует: она и так оставляет `voices/` и записи
  других книг.

### Безопасность

Все маршруты — только книги своего workspace: список фильтруется по `workspace_id`, маршруты `/book/:id/*` —
`requireBookAccess` (аноним 401, чужая 403). Тесты: `backend/tests/my-books.test.js` (чужая книга 403 на
`/opened`, `/cache`, `DELETE /book`; аноним 401; обработчики при этом не вызываются).

## 5. Настройки

Блок «Очистить» («Удалить vBook с сервера», «Удалить Сторибоард с сервера») **убран**: кнопки действовали на
открытую книгу, а экран её не показывал. На его месте — пункт **«Мои книги»** (§1). Удаление книги и её
контента — только из списка, по книге, с названием в подтверждении.

## 6. Экран книги 3.1

Книга 3.1, которую пользователь попытался открыть (deep link, «Открыть»), показывается на экране «Файл»
текстом «Формат книги не поддерживается…» **и кнопкой «Удалить книгу»** с тем же подтверждением (§3):
web `features/myBooks/UnsupportedBookPanel.tsx` (рядом с `FilePage`, пакет `@animastor/web-file` не менялся),
Android `fragment_file.xml` `unsupportedBox`. Та же кнопка — в состоянии 3.1 редактора (web `BookProblems.tsx`
`UnsupportedBook`, Android `EditFragment.buildUnsupportedBook`). Восстановление сессии при запуске никогда не
выбирает книгу 3.1 (первая поддерживаемая книга списка).

## 7. Web: адрес `/library` на app.animastor.org

До 2026-11-24 nginx на `app.animastor.org` отдавал `location = /library` публичной страницей сайта, а не SPA:
внутри приложения переход работал (history API), но прямая загрузка или обновление `/library?tab=mine` открывали
публичную страницу. Правка `animastor-deploy` `nginx/default.conf` — блок `location = /library` удалён из
`app.animastor.org`, его отдаёт SPA-fallback `location /`; выкачено 2026-11-24 вместе с web (deploy `fd4027c`).
Публичная страница библиотеки — `animastor.org/library`, не менялась.
